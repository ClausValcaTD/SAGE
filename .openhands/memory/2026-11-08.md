## Task 2 — textures (the real work)
- Symptom: 3D layer flat-shaded; `SAGE_PPM3D` dump had only 10 unique colours.
- Investigation: instrumented `render_one` renderer counts (`solid=34248
  solidT=948 tex=323903 texT=30540` — textured polys WERE dispatched) and
  `fetch_bilinear_texel`. `poly.luma` (176-255) and `poly.lumabase` (12544-12800)
  were sane, but the luma *curve* value was always 0.
- Root cause: luma RAM `0x11400000-0x1140ffff` is `umask16(0x00ff)` on Model 2B —
  one byte per 16-bit half-word. SAGE mapped it as a byte window, so word writes
  landed on even offsets (12204 even / 0 odd nonzero) and `lumaram[lumabase +
  (t>>1)]` read zeros. Fix in `src/bus.cpp`: explicit half-word decode in all
  read/write widths, BURST flag preserved, removed from `Bus::map()`.
- Result: 3D layer 10 → 703 colours, composited frame 25 → 718.
- Reverted all temporary instrumentation before committing.

## Audiovisual showcase video
- Captured 3,600 frames with `SAGE_HEADLESS=1 SAGE_RAWVIDEO=/tmp/sage_raw.rgb
  SAGE_WAV=/tmp/sage_audio.wav ./build-release/sage roms/doa.zip doa 3600`.
  Raw RGB24 = 496*384*3*3600 = 2,057,011,200 bytes exactly; WAV = 16-bit stereo
  44.1 kHz, 10,584,016 PCM bytes = 60.0001 s. Both exactly 60.0 s — the SCSP
  pending-sample path keeps audio/video in lockstep.
- Encode (ffmpeg 7.1, installed via `sudo -n apt-get update && apt-get install -y
  ffmpeg`):
  `ffmpeg -y -f rawvideo -pix_fmt rgb24 -s 496x384 -r 60 -i raw -i wav
   -vf "scale=992:768:flags=neighbor" -c:v libx264 -crf 30 -preset slow
   -pix_fmt yuv420p -c:a aac -b:a 192k -movflags +faststart out.mp4`
  → 23.2 MB, h264 992x768@60 + aac 44.1k stereo, 60.0 s.
- Verify: decoded frames show textured models (unique colours ~77k-110k after
  2x upscale; mean |diff| vs source ~7-8 = h264 noise). Decoded audio peak 16586
  / rms 1825, matching the source (peak 17157 / rms 1842).
